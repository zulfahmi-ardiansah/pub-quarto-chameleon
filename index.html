Why Qlon exists

Keep the writing simple. Make the handoff familiar.

The place where I want to write a document is often different from the format people expect to receive.

I built Qlon because writing documentation in Word turned every revision into formatting work. Markdown lets me keep the source near the code, review changes in version control, and use drafts generated from source code.

But people still need a DOCX they can open and pass along. Qlon gives those chapters a cover, images, and a Word style without making me rebuild the handoff each time. Same source, a different look. Just like a chameleon.

  • Keep chapters as filesWrite .md or .qmd chapters and order them by filename. Qlon stages copies during rendering, so your original files remain the source you revise.
  • Reuse a Word styleStart with the included template, or bring a reference DOCX that carries your fonts, headings, headers, and footer across every render.
  • Bring visuals with the textRelative image paths are copied into the workspace, and Mermaid diagrams become images. Oversized visuals are scaled to fit the Word page.
  • Go back to MarkdownStarting from Word? Qlon extracts a DOCX into Markdown pages and a media folder, giving you files you can inspect and edit again.

The result

A document people can open in Word.

The finished DOCX contains a cover, the assembled chapters, and styles from the reference template. Qlon also fills changing header text, fits oversized images and tables to the page, and can export images alongside the document.

Choose your route

Use a browser or make it part of your workflow.

The browser wizard is useful for a one-off document or a pasted draft. The CLI keeps the document recipe beside your chapter files so you can render it again after a revision. Both use Qlon's local render pipeline; this page is a guide, not a hosted converter.

Browser wizard

Bring content without writing a config.

Run the web interface locally, then paste Markdown, upload chapter files, or add a ZIP project containing text and images. Enter the cover details, choose a template, review, and download the DOCX.

The Docker setup bundles the rendering tools. Once it starts, open localhost:5000 in your browser.

docker compose up --buildRead the browser guide
Command line

Keep a repeatable document recipe.

Write a YAML file with the cover, content folder, and optional template. Point it at your .md or .qmd chapters, then run the same command after each revision. The DOCX goes to your current directory unless you set --output.

Windowsbin\qlon.bat config.ymlLinux / macOSbin/qlon.sh config.yml
Read the CLI guide

The CLI needs Python, Quarto, and Playwright installed as described in the README. On Linux or macOS, make bin/qlon.sh executable once before running it.

What it handles

The details that make a document usable.

Qlon uses Quarto for the document build, then adjusts the Word file where a simple format conversion would leave work for you. These steps are part of the renderer, whether you use the wizard or the CLI.

Structure
Chapters are sorted by filename, placed after the cover, and listed in a table of contents field. Give files numeric prefixes when their order matters.
Visuals
Relative images and Mermaid diagrams are collected for the document. Qlon scales down images that would overrun the page while keeping their proportions.
Word layout
Header placeholders are replaced with your document details, and tables are set to fit the available page width. The Word template remains the source of visual styling.
Reverse path
Need the source back? Qlon can also extract a DOCX into Markdown pages and a media folder. Read about reverse mode.
